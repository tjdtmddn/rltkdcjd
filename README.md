# 기상 관측자료 수집

기상청 APIHub의 지상 관측자료 조회 API에서 관측소 `108`의
2025년 10월 1일 00시부터 10월 7일 23시까지 1시간 간격의 자료를 요청합니다.
요청에는 도움말(`help=1`)을 포함하며, 출력 데이터는 관측 시각·기온·습도·풍속
열을 대상으로 합니다.
원본 46개 열 중 `TM`(1열), `WS`(4열), `TA`(12열), `HM`(14열)을
공백 기준으로 분리해 추출합니다. 기온의 `-9` 값은 정상적인 관측값일 수 있어
일괄 삭제하지 않습니다.

## 실행

```powershell
python -m pip install requests pandas
python collect_weather.py
```

실행 중 인증키를 입력하면 HTTP 상태가 출력됩니다. 성공하면 원본 응답을
`weather_raw.txt`로 보관하고, 다음 열을 `weather.csv`로 저장합니다.

```text
datetime,temperature_C,humidity_pct,wind_speed_ms
```

자료 행은 `#` 설명 행을 제외하고 공백으로 분리하며, 공식 헤더의 열 번호
`TM(1)`, `WS(4)`, `TA(12)`, `HM(14)`를 사용합니다. 시간순 정렬과 중복 확인을
수행하고 CSV는 인덱스 없이 `utf-8-sig`로 저장합니다. 결측값은 빈 칸으로
저장하며, 정상적인 음수 기온(예: `-9`)은 삭제하지 않습니다.
표 정리에는 pandas의 `to_datetime()`, `to_numeric()`, `sort_values()`,
`isna().sum()`, `to_csv()`를 사용하며 변환 실패와 중복 시각 개수도 출력합니다.

인증키는 파일에 저장하지 않으며 출력에도 포함하지 않습니다. 자료가 없으면
`weather.csv`를 생성하지 않고 원인을 안내합니다.

활용신청이 필요한 API라는 응답이 나오면 기상청 APIHub에서 해당 API의 활용신청을
완료한 뒤 다시 실행합니다. HTTP 401은 인증키를, HTTP 403은 활용신청 상태를
확인합니다.

## 기온·습도·풍속 그래프

API를 다시 호출하지 않고 기존 `weather.csv`를 사용해 그래프를 생성합니다.

```powershell
python -m pip install matplotlib
python plot_weather.py
```

`plot_weather.py`는 `datetime`을 시간으로 변환하고 시간순 정렬 후 1시간 간격으로
누락 시각을 확인합니다. 기온 그래프는 `temperature.png`, 습도와 풍속 그래프는
`humidity_wind.png`로 저장하고 화면에도 표시합니다.

## 제출 확인

- 관측소: `108` (서울)
- 기간: `2025-10-01 00:00` ~ `2025-10-07 23:00` (KST)
- 출처: [기상청 APIHub 지상관측자료](https://apihub.kma.go.kr/api/typ01/url/kma_sfctm3.php)
- 제출 파일: `collect_weather.py`, `plot_weather.py`, `weather.csv`,
  `weather_raw.txt`, `temperature.png`, `humidity_wind.png`, `README.md`

확인 결과 자료는 168행이며 시간 누락과 중복 시각은 각각 0개이고,
`datetime`, `temperature_C`, `humidity_pct`, `wind_speed_ms`의 결측값도 모두 0개입니다.
그래프에서는 2025년 10월 1~7일의 시간별 기온·습도·풍속 변화를 확인할 수 있습니다.

인증키는 코드, CSV/원본 응답, 이미지, README에 저장하지 않았으며 실행 시
`getpass.getpass()`로만 입력합니다.

## 풍속 예측 회귀 실험

`asos_108_2023_2024.csv`를 1시간 간격으로 맞춘 뒤, 필요한 값이 모두 있는
행만 `wind_dataset.csv`에 저장했습니다. 입력은 예측 시각에 알 수 있는 현재
풍속·기온·습도와 정확히 1·2시간 전 풍속 5개이며, 정답은 정확히 1시간 뒤의
실제 풍속입니다. 누락 시각은 빈 행으로 먼저 만들고 빈값은 보간하지 않았습니다.

```powershell
py -3 build_wind_dataset.py
py -3 train_evaluate_wind.py
py -3 plot_prediction_week.py
```

학습은 정답 시각이 2023년 1월부터 2024년 11월까지인 16,720행으로 수행하고,
평가는 정답 시각이 2024년 12월 1일부터 31일까지인 744행으로 고정했습니다.
평가 중 재학습하지 않았으며, 시각은 KST입니다. 선형회귀와 랜덤포레스트
(나무 100개, 최대 깊이 6, `min_samples_leaf=5`, `random_state=42`)를
현재 풍속 유지 기준과 비교했습니다. 음수 예측은 0으로 바꿨습니다.

| 방법 | 12월 MAE (m/s) |
|---|---:|
| 현재 풍속 유지 | 0.653495 |
| 선형회귀 | 0.594577 |
| 랜덤포레스트 | 0.593807 |

선형회귀는 기준보다 0.058918 m/s(9.02%) 낮았고, 랜덤포레스트는 기준보다
0.059688 m/s(9.13%) 낮았습니다. 랜덤포레스트는 선형회귀보다
0.000770 m/s(0.13%) 낮았습니다. `predictions.csv`에는 같은 정답 시각별
실제값과 세 방법의 예측값을 저장했습니다.

### 크게 틀린 시각

12월 전체에서 절대오차가 큰 사례는 다음과 같습니다.

| 정답 시각 (KST) | 실제 (m/s) | 기준 (m/s) | 선형회귀 (m/s) | 랜덤포레스트 (m/s) |
|---|---:|---:|---:|---:|
| 2024-12-30 12:00 | 3.7 | 0.5 | 0.948 | 1.067 |
| 2024-12-18 23:00 | 0.7 | 3.8 | 3.320 | 3.176 |
| 2024-12-28 05:00 | 4.4 | 2.0 | 2.038 | 1.982 |
| 2024-12-02 13:00 | 3.6 | 2.1 | 1.356 | 1.512 |

예를 들어 12월 2일 13시에는 실제 풍속이 3.6 m/s로 급증했지만 선형회귀는
약 1.36 m/s로 예측해 2.244 m/s 낮았습니다. 12월 30일 12시에는 실제
3.7 m/s인데 기준은 0.5 m/s, 선형회귀는 0.948 m/s, 랜덤포레스트는
1.067 m/s로 모두 급증을 충분히 반영하지 못했습니다. 반대로 12월 18일
23시에는 실제 0.7 m/s인데 직전 풍속이 높아 세 방법 모두 높게 예측했습니다.

첫 주 12월 1~7일의 실제값, 기준 예측, 선형회귀를 한 그림에 비교한 결과는
`prediction_week.png`입니다. 첫 48시간 확대 결과는
`prediction_week_first48.png`입니다.

### Copilot 요청과 직접 확인 결과

- 요청: 정확히 1시간 뒤 풍속을 정답으로 두고, 시간순 분할·고정 평가·MAE 비교·
  그래프·큰 오차 분석을 수행했습니다.
- 직접 확인: 모든 평가행에서 `target_time - prediction_time`은 정확히 1시간이고,
  12월 정답 시각은 744개이며 1시간 간격·중복 0개·결측 0개입니다.
- 입력에는 현재와 과거 풍속, 현재 기온·습도만 있고 미래 정답 풍속은 넣지 않았습니다.
- 학습은 2024년 11월까지, 평가는 2024년 12월 정답만 사용했습니다.
- 두 학습 모델 모두 같은 평가 시각에서 기준보다 MAE가 낮았습니다.
- `prediction_week.png`에서 급증·급락 시 실제값과 예측값의 차이를 시각적으로
  확인할 수 있으며, 위 표의 시각·값으로 설명할 수 있습니다.
